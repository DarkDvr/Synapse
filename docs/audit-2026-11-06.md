# Audit — 6 November 2026

A housekeeping pass and a coding-practices review of the code as it stands at
1.29.2. Everything below was measured in this checkout; nothing is remembered from
an earlier version.

## The shape of it

| | |
|---|---|
| `src/` | 20,330 lines in 51 files |
| `web/` | 11,142 lines of JavaScript, 3,294 lines of CSS |
| `tests/` | 73 files, 497 tests, `node --test`, no dependencies |
| `skills/`, `templates/`, `shell/` | 30 files, 26 files, 75 files |
| Runtime folder | `bin\` 1.3 GB (Node + engine), `data\` 688 MB (engine home, WebView2 profile) |

The two big files are the story of the codebase: `web/app.js` is 10,546 lines and
`src/runs.js` is 3,895. `src/api.js` (2,385) and `src/plans.js` (1,420) follow.
Everything else is under 1,000.

## What the code does well

Worth saying before the criticism, because it is unusual:

- **One contract per concern.** The engine sits behind `src/engines/base.js`, the
  permission policy behind `permissions.js`, the plan behind `plans.js`. Swapping
  the engine is one file, and that has stayed true for 1.29 versions.
- **The comments explain why, with the incident and the measurement.** Most
  files open with the bug that shaped them. That is why a new agent can work here
  at all.
- **The tests are honest about their level.** 497 tests, no network, no clock
  flakiness, fixtures inline.
- **Zero dependencies held for 1.29 versions.** No build step, no lockfile drift,
  no supply chain.

## What should change

Ranked by value against risk. Nothing here is a bug report; these are the things
that will cost the most time later if they are left.

### 1. `web/app.js` is 10,546 lines in one module

It holds the transcript, the composer, the rail, the cards, the plan pane, the
settings pages, the update dialog, the ask panel, the desk badge and the SSE
handler, over one mutable `state` object with roughly a hundred fields. Every UI
change is a search through it, and two of this month's bugs (the double-submit
toast, the stale stop notice) were a handler reaching a node it did not own.

*What I would do:* split it by screen — `transcript.js`, `composer.js`,
`rail.js`, `settings.js`, `updates.js`, `events.js` — with the shared `state`
imported from one `state.js`. It is mechanical and it is risky in exactly one way
(the load order of event handlers), so it should be done behind the existing UI
tests, one screen per commit. Not in one afternoon.

### 2. The path normaliser is written fourteen times

`String(value).replace(/\\/g, '/').replace(/\/+$/, '').toLowerCase()` exists as
`normDir`, `norm`, `dirKey`, `key`, `asKey` and `slash` in twelve files, with two
different behaviours (some lower-case, some do not). That is how "the same folder"
became a bug class: every comparison is only as correct as the copy it used.

*What I would do:* one `normDir` and one `slash` in `paths.js`, imported
everywhere. Roughly forty lines disappear and one behaviour remains.

### 3. 179 catches say nothing at all

More than half of the `catch` blocks in `src/` have no binding and no comment.
Some are right ("a session that is gone is quiet"), but a reader cannot tell a
deliberate swallow from a forgotten one, and a real failure disappears silently.
The Stop bug hid in exactly this: `interrupt` failing during a retry wait threw
nothing anyone could see.

*What I would do:* a rule, not a refactor — a bare `catch` must carry a comment
naming why it is safe, and anything that talks to the engine logs at `warn` once.
Then a small pass over the ones that talk to the engine.

### 4. No `npm test`, no CI

`package.json` has `start` and `dev` and no `test`; the suite is only ever run by
hand with the full `node --test "tests/*.test.mjs"` line. There is no `.github/`
folder, so a push that breaks the suite is discovered by the operator.

*What I would do:* a `"test"` script in `package.json`, and a GitHub Actions
workflow that runs it on push to `main` (Windows runner, `node --test`). It costs
one file and it turns "497/497" from a claim into a gate.

### 5. `src/runs.js` carries four jobs

The worker loop, the Architect's wake loop, the report writer and the run ledger
are one file. The wake loop is the part that has caused the most incidents
(stopping it, holding the project, a report that wakes it again) and it is the
part least entangled with the rest.

*What I would do:* extract the wake loop into `src/wake.js` first. It has a clear
seam (`waitForIdle` plus the retry ladder) and its own tests.

### 6. Event names are string literals everywhere

`'session.step.started'`, `'session.retry.scheduled'`,
`'session.execution.interrupted'` appear in `index.js`, `runs.js`, `api.js`,
`stop.js`, `web/app.js` and the tests. A typo is silent — the handler simply never
runs — and the adapter is the only place that should know them.

*What I would do:* one `src/events.js` of names, used by the adapter and the
consumers, with the raw strings confined to `engines/opencode.js`.

### 7. Synchronous filesystem calls in the request path

89 `readFileSync`/`writeFileSync`/`existsSync` calls in `src/`. For a local app on
one machine this is defensible — the files are small and the OS caches them — but
a plan read on every poll, on the same thread that serves the stream, is the kind
of thing that shows up as "the UI froze for a moment".

*What I would do:* not a rewrite. Cache the plan by mtime (it already has one),
and move the two or three hottest reads to `fs/promises`.

### 8. Errors are shaped by convention, not by type

Routes set `err.status`, `err.body`, `err.busy` by hand in each handler. It works,
and the client reads it, but every new route re-invents the shape.

*What I would do:* one `fail(status, message, extra)` helper in `src/errors.js`,
used by `api.js`. Ten lines, and the client contract becomes visible in one place.

### 9. 49 exports nobody imports

The audit found 49 exported names with no importer — most are used inside their
own file and simply exported too widely (`plans.js` alone has nine). Five were
truly dead and are gone.

*What I would do:* un-export the rest as files are touched, not in a sweep. An
export is a promise; a file with nine of them for its own use is lying about its
surface.

### 10. The tests agree with the code, not with the engine

The Stop rebuild is the lesson: 497 green tests, and the engine still retried
through five Stops because the fakes modelled a world where one interrupt is
final. Unit tests cannot catch a wrong model of the engine.

*What I would do:* one opt-in contract test (`SYNAPSE_E2E=1`) that starts the
real engine, runs a two-turn session and asserts the event names and the idle
marker. It is the test that would have caught this in October.

### Smaller things, done or worth a line

- `package.json` `description` said "Chat with OpenCode free models" — the harness
  is model- and engine-agnostic now. Corrected in this pass.
- `docs/notes/todo.md` did not exist but four files pointed at it. Created.
- `AGENTS.md`'s note index omitted `releases.md`. Added.
- The release notes stop at v1.14.0 while the app is 1.29.2; versions 1.15–1.29
  have no note. Either write them going forward or stop keeping the folder.

## What has been done since this report

- **#2 (the path normaliser)** — done. `paths.js` holds `normDir` and `slash`; the
  fourteen copies are gone, including the two in `runs.js` that disagreed with each
  other.
- **#4 (no `npm test`, no CI)** — done. `package.json` has a `test` script and
  `.github/workflows/tests.yml` runs the suite on every push to `main`. Its first
  run found two tests that only passed on a machine with local state: one read the
  provider diary (which is deliberately silent under `node --test`), one waited 40
  seconds for a run that needs longer on a loaded runner. Both fixed.
- **#9 (49 exports nobody imports)** — done, mechanically.
- **#10 (a contract test against the real engine)** — done,
  `tests/engine-contract.test.mjs`, opt-in with `SYNAPSE_E2E=1` and read-only.

Still open: **#1** (split `web/app.js`), **#3** (catch discipline), **#5** (extract
the wake loop), **#6** (event-name constants), **#7** (sync fs on the request
path), **#8** (an error helper). #1 and #5 are structural and want their own
session with the app running; the rest are small.

## What I did not change

- **The engine home and the WebView2 profile.** 688 MB, and both are live state.
- **`web/synapse.css` at 3,294 lines.** One file is the right call with no build
  step; splitting it would cost requests to save nothing.
- **The one-chat-per-project model and the plan file contract.** Those are
  decisions with their own notes, not code smells.
- **The release notes folder.** History, and cheap to keep.
