## What Synapse is now

It was a server you started in a terminal. It is a Windows application now:

- **`Synapse.exe`** at the folder root — one lean file, built by `.\shell\build.ps1`
  (about 1.5 MB, needs the .NET 10 runtime). Closing it hides the window to the tray;
  the tray starts, stops and restarts the server, and Exit stops both.
- **The console lives in the window.** The `…` beside Runtime opens it, with
  **Start**, **Restart**, **Stop** and **Close** — the same four things the tray menu
  does. The server's own output is written to `logs\console.log` by the app, so the
  panel still works when the server is not running.
- **The folder travels.** Copy it to another PC with the .NET 10 runtime and it runs.
  No `F:\dev\Synapse` in a config, no ghost project from a machine it has never seen.
- **A good tenant.** Whatever it needs, it fetches into its own folder. npm is pulled
  into `bin\node` when the machine has none; nothing goes to `%APPDATA%`, PATH,
  `winget` or the registry.

## Verified, with the numbers

- **Portability, on a second PC.** The engine was dead, `F:\dev\Synapse` was created on a
  machine with no F: drive, and a project folder that does not exist was listed. All three
  fixed at boot: a dead path is cleared, a missing project is dropped, the engine falls back
  to the copy that travels. `tests/portable-paths.test.mjs` holds all four checks.
- **A crash.** Killing the app left **8 processes** holding 8700 and 8720. Relaunch now
  prints one console line (`stopping a server left by a previous run`) and starts normally.
- **It only stops what is ours.** Both pid files were pointed at Notepad; Notepad stayed
  alive and the server started. The selector proves the executable lives inside the folder
  and refuses anything under `@opencodedesktop`.
- **The window.** Maximised on exactly 2560×1400; restored at 1200×780; all eight edges and
  corners return the right resize code; the title bar cannot be dragged off-screen.
- **The console actions** measured `rgb(53,192,138)` / `rgb(237,194,90)` / `rgb(240,86,63)`
  with transparent fills — border and label only, as the palette requires.

## Not done on purpose

- **Stop Server's confirmation is a native dialog.** It must be answerable when the page is
  not, so it cannot live in the page.
- **The exe is unsigned**, so a fresh machine gets SmartScreen once.
- **The title bar uses Segoe.** WPF cannot load the vendored WOFF2 fonts.
- **A crash still leaves its orphans for the next launch** rather than cleaning up as it dies;
  that launch does it silently now.

---

## Three traps that still cost time

1. **Never match a process by name.** `Get-Process -Name opencode` also matches the operator's
   `OpenCode.exe` desktop app, whose path contains `@opencode`. Pids from `data\*.pid` and a
   path check inside the folder; dry-run a selection before acting on it.
2. **A brief change that lands while the server runs has not landed.** Check the boot line in
   `logs\app.log` before deciding a rule does not work.
3. **Ports 1174–1273 are reserved** on this machine by Hyper-V/WSL. UI is 8700, engine 8720.
