# What we are changing, and how to put it back

A short sheet for the operator, not a lesson: the behavioural changes we are making to
the harness, why each one exists, and the tag to return to if it turns out worse in a
real run than it looked on paper. The reasoning lives in `docs/notes/`; this is the
undo list.

**How to go back**

- One change: `git revert <commit>` and rebuild — the commit is named in the table.
- Everything since a point: `git checkout v1.36.0`, `.\shell\build.ps1`, run. A tag is a
  working app, not just a label.
- Nothing here touches `config\synapse.config.json` or a project folder, so a rollback
  never costs a project its settings, its plan or its history.

## Landed

| version | what changed | why | if it is worse |
|---|---|---|---|
| 1.36.2 | **The harness writes `doing`, not the Architect.** `doing` is set when a worker starts and released to `todo` when the run ends, whatever the outcome. The brief says not to write it. | A row said "doing" while nothing ran — after a stop it read "1 running" for the rest of the day — and the model was keeping a fact it cannot see. The model keeps the judgement (`todo`/`done`/`blocked`/`failed`); the harness keeps the mechanics. | `git revert 65315b3`, or roll back to **v1.36.1**. Watch for: an Architect that no longer notices a task is in flight, or a row stuck on `todo` while a worker is on it. |
| 1.36.3 | **The page's tests ask it what it rendered**, against a small fake window (`tests/fake-page.mjs`) instead of searching its source for a phrase. | A phrase test fails when a sentence moves and passes when the behaviour is broken. Three chat behaviours are asserted this way now, and the rest will follow as they are touched. | Nothing in the app changed — only the tests. Roll back with the commit if the suite gets slower or flakier. |
| 1.36.4 | **The brief is three sections**: `What never changes`, `How we work`, `This round`. Five sentences that are rules rather than habits moved to the top, once each; the project's own state is the tail. Single mode has no sections. | The brief had become one pile, with a project's situation at the bottom of three thousand tokens and the rules that cost something buried in the middle. Order is the fix; no rule was rewritten. | `git revert` this commit or roll back to **v1.36.3**. Watch for: an Architect that ignores a rule that used to be further down (the text is identical, so this would mean the model reads position rather than content — worth knowing). |
| 1.36.5 | **Processes are a refused shape.** A kill that sweeps a list, names a shared runtime (`python`, `node`, `pwsh`…), or stops an id it looked up is refused with no card. A specific `-Id` and a project's own app by name are still allowed. | The path fence cannot see a kill: the worker that stopped the model server named no file. The refusal says what to do instead, and an unattended run is not made to wait. | `git revert` this commit or roll back to **v1.36.4**. Watch for: a legitimate by-name kill of something whose name is a runtime (a project's own `python.exe` build), or a script that stops processes inside itself. The full rule is in `docs/notes/protection.md`. |
| 1.36.6 | **Strength-test fixes.** Kills reached by another route (`.Kill()`, WMI, `wmic`, `taskkill /FI`, `?` wildcards, nested `powershell`/`cmd` shells, a `.ps1` that sweeps) are refused; Windows tools' `/Switches` are no longer read as paths; `t2a1` is drawn under `t2`; a project document can no longer forge a brief section. | Adversarial probes written before trusting the changes (docs/strength-tests.md) found eight holes in the process rule alone, one injection into the brief, and a mismatch between a documented plan rule and the code. | `git revert` this commit or roll back to **v1.36.5**. Every refusal is covered by a test, so a revert that keeps the tests will fail loudly rather than quietly re-open a hole. |
| 1.36.7 | **A pid the model recorded may be stopped.** `Stop-Process -Id $serverPid` / `taskkill /PID $pid` are allowed; the refusal now covers the shapes that carry a *list* (`(`, `$_`). | Refusing `-Id $anything` refused the exact pattern the brief asks a model to use, while `taskkill /PID $pid` slipped through. | `git revert` this commit or roll back to **v1.36.6**. Watch for: a kill that names a list and is allowed because it is a plain variable. |
| 1.36.8 | **A task that produces evidence names `.synapse/reports/`, not `bin/`.** The Architect's brief says it as well as the worker's. | A coder asked for "the proof" put it in `bin/`, the folder the Architect's brief calls the place for deliverables, because the task detail outranked the worker's brief. | `git revert` this commit or roll back to **v1.36.7**. See 1.36.11: the rule this version stated was refused by the write policy until then. |
| 1.36.9 | **A done row owes a result; a ceiling per brief; another phrase test became a render.** | `done` with no `result` is a plan problem now; the brief has a size ceiling, so a new rule must be paid for by removing one. | `git revert` this commit or roll back to **v1.36.8**. Watch for: an Architect whose plan now reports a problem on a row it used to leave empty. |
| 1.36.11 | **Evidence is a shared folder.** Every role may write `.synapse/reports/`, the stray-write check ignores it (as it already ignored `shots/`), and the cleanup mover marks the files it moves into `.synapse` as the harness's own writes. | The brief tells every role to keep proofs in `reports/` while the write rule denied exactly that folder, so a coder's `write` was refused, it fell back to a shell redirect, and the tamper alarm reported its compliance as tampering (10 Nov, t4b). | `git revert` this commit or roll back to **v1.36.10**. Watch for: a worker keeping evidence in a folder the operator expected to be role-owned — that is the change, not a regression. |
| 1.36.12 | **A pid read from a file may be stopped, even beside a process list.** The "something listed processes and something stopped one" test now excuses an explicit id that is a number or a plain `$variable`; `(`, `$_`, a family name and a wildcard are still refused. Two log fixes ride along: the repeated `pending` read warning is one line a minute, and answering a request the engine has already closed is debug, not a warning. | A live QC run's own cleanup — `Stop-Process -Id $p` in a loop over two pid files, with a read of the process list beside it — was refused, so the worker had to find another way to stop the app it had started (docs/strength-tests.md). And `app.log` carried 2,077 identical lines, which is the noise that hides the line that matters. | `git revert` or roll back to **v1.36.11**. Watch for: a kill that reaches several processes through a variable holding a list — that shape is allowed, and it is the one the 1.36.7 change already accepted. |
| 1.36.13 | **A program a launcher names is a run; elevation is refused as itself; a row for the Architect is not a delegation.** `Start-Process …\powershell.exe` is allowed (the program is in an argument, where the head-of-statement rule could not see it); `-Verb RunAs` is refused with the real reason — an unattended run cannot answer the UAC prompt — instead of "PROHIBITED: Windows is on the protected list". A plan row whose role is `architect` is refused and handed back to the Architect to do itself. Also: the alarm line is one line with "…", the Architect's post opens at the start of its turn with "Thinking…", a shipped render started from a `file:///` URL no longer raises the second "named Synapse" alarm, and a steer's "You" sits on the sentence's centre line. | The operator's screenshot of one turn showed a false PROHIBITED line, a wrapped warning, a duplicate warning, an empty Architect box while it thought, a label a couple of pixels high — and a delegation the Architect made to itself, drawn as a yellow loop on its own card (11 Nov). The duplicate had a root cause worth keeping: a CSS comment above `.chat-alarm` had lost its opening marker, so the browser parsed the sentence as CSS and dropped the whole rule — the ellipsis had never applied. | `git revert` or roll back to **v1.36.12**. Watch for: a model that now runs `Start-Process` on a system program without a card — that is the change; elevation still refuses, a write into Windows is still prohibited, and an Architect that must settle its own rows instead of delegating them. |
| 1.38.0 | **SynaBrowse: the harness gets a browser of its own.** A hidden real Edge with its own profile (`data\browser\profile`, never the operator's), driven over CDP: open, read, click, type, press, wait, scroll, screenshot, watch frames, tabs. A page that needs a human brings the window to the second monitor **minimized on the taskbar**, blinks its button and chimes — it never takes focus. Off by default, fenced by a per-host allowlist. | `webfetch` is refused by Cloudflare and cannot sign in; a hidden headed Edge cleared the same challenge in 2.6 s while headless never did, and a signed-in session opened the deep routes that had answered "Something went wrong." (docs/plan-synabrowse.md). The tools can act as the operator, so they exist only when switched on. | `git revert` this commit or roll back to **v1.37.0**. Watch for: a model clicking through an allowed site on its own — that is the feature, and the allowlist plus the operator's attendance are the control. |
| 1.39.0 | **Settings → Browser, and the tamper alarm stops crying wolf.** A twelfth tab: the enable switch, the profile folder, the allowlist (one host per line) and **Sign In…**, the one control that acts without Save — it puts that browser on the second monitor so a person can log in. And the "shell command naming the harness" alarm now fires on a **write shape** (a write verb, a redirect into the harness, a .NET write, or a harness script being run) instead of on "not every piece was a read verb"; a command that lists the toolbox is a log line again. | A QC run's own multi-line `git grep`/`Get-Item` block raised the popup on 11 Nov — the third false positive in a week — and a false alarm teaches the operator to skip the line that matters. The ruleset, the run-long status comparison and the snapshot still catch the write. | `git revert` or roll back to **v1.38.1**. Watch for: a write reached by a tool this list does not know (it would be logged, not alarmed) — the `git status` comparison around the run is the backstop. |
| 1.40.0 | **The Browser tab lists the sessions, not the permissions.** The host allowlist is gone: the master switch is the fence, and a **Sites** table (Prohibited's shape) records each host signed into, when, and when it was last used, with ✕ to forget — the row and that host's cookies together. Sign In now reports its progress in the pane, and closing the window after signing in raises **"Session Kept"** and writes the row. | The operator's own answer to "which sites may it open" was "the ones I am logged into", and a host list they would fill with `*` is a list that lies about being a fence. The sign-in click sat silent until the browser was up, and nothing said the login had been saved (11 Nov). | `git revert` or roll back to **v1.39.2**. Watch for: a model browsing a site the operator has not signed into — that is the change; the switch still turns the whole thing off. |
## Not doing (decided 10 Nov)

- **A claim/intention field on tool calls.** Paths could be checked against a declaration
  and processes only partly; anything a harness cannot contradict is theatre, and the
  process rule above covers the failure that cost the model server.
- **A fence around the shell.** Out of scope for now.
- **Removing `result` / `note` / `origin` from the plan.** It moves information into logs
  rather than out of the model's hands.

## Not changing

- The dependencies, the engine adapter, the single-operator design — deliberate, and
  tested where it counts.
- The plan's other fields (`result`, `note`, `origin`): removing them moves information
  into logs rather than out of the model's hands.
